# 集体记忆（Collective Memory）

## 概念

所有项目共享一个**中央记忆库**，存放在 Claude 用户配置目录下（本技能安装在用户级 `~/.claude/skills/`，因此在**任何目录的任何项目**里都可用）：

```
~/.claude/global-memory/
├── MEMORY.md        ← 索引：每条记忆一行，每次会话经用户级 CLAUDE.md 自动加载
└── *.md             ← 每条记忆一个文件，带 frontmatter
```

单一真相源：所有项目读写的都是这一个文件夹，零副本、零分叉、不进任何 git 仓库。
（备选方案「复制记忆到每个项目文件夹」已否决：密钥泄露风险 + 版本分叉 + 无关记忆污染。）

## 核心流程

### 1. 开工前召回（Recall）—— 防走弯路的关键

每次开始一项新任务（写代码、排查、决策）之前：

1. 读 `MEMORY.md` 索引；
2. 按任务关键词（项目名 / 技术栈 / 领域）匹配索引行的 hook 与文件的 description；
3. **只读相关的那几篇**，绝不全量读入 —— 无关记忆反而会干扰判断；
4. 按其指引行动；若记忆与当前现实矛盾 → **以现状为准**，并把记忆改正。

### 2. 收工前沉淀（Save）—— 每条记忆单独经用户确认

工作结束后（或用户说「记下来」「记住」「记录记忆」等）触发；触发后直接进入候选确认流程，不要重复展示技能正文。

1. 提炼**候选记忆清单**：每条可复用的经验 / 偏好 / 事实单独成一条，不写流水账；
2. **逐条、单独向用户确认**：一条记忆单独问一次「写 / 不写」（AskUserQuestion 单条提问，**严禁把多条记忆打包成一次多选**）：
   - 每条提问写清：内容摘要 + 为什么值得记；
   - 用户选「不写」的候选 → **一律不写入**；
   - 候选较多时按重要程度排序，逐条问完为止；
3. 只把用户确认「写」的记忆按下方格式写入新文件，文件名 = `name` slug；
4. 写入后更新 `MEMORY.md` 索引；
5. 已存在同类记忆 → 先单独展示更新方案并经用户确认，再**更新旧文件**而不是新建（防重复、防分叉）。

无论是用户明确要求记录，还是收工前的自动沉淀，都必须逐条走上面的确认环节，**绝不允许未经确认直接写入，也不允许打包成一次多选提问**。

### 3. 维护（List / Clean / Update）

- 记忆被证明错误 → 直接删除或改写该文件，并同步更新索引行；
- 两条记忆高度重复 → 合并为一条；
- `list`：读索引即可；`clean`：核对索引行与实际文件一一对应，清理失效条目。

## 记忆文件格式

```markdown
---
name: <short-kebab-case-slug>
description: <一句话，用于召回时判断相关性>
metadata:
  type: user | feedback | project | reference
  project: <来源项目名；跨项目经验写 cross-project>
---

<事实/经验本身>

**Why:** <为什么成立>
**How to apply:** <怎么用>
```

type 含义：`user`=关于用户的角色与偏好；`feedback`=用户给的工作方式反馈；`project`=项目状态/目标/约束；`reference`=外部资源指针。

## 铁律

1. **禁止写入**：密码、API key、token、账号凭据、身份证号等敏感信息。记忆库会被所有会话读取，写进去等于广播。
2. 一条记忆一个事实；不整段搬运代码。
3. 召回时选择性读取 —— 索引每次必读，正文按需。
4. 记忆是过去的快照，应用前先验证是否仍然成立。
5. 不重复已有记忆：更新旧文件，而非新建。
6. **写入前必须逐条经用户确认**：新写入或更新记忆（包括收工前的自动沉淀）都要一条记忆单独问一次「写 / 不写」，确认一条写一条；未确认的一律不写，严禁打包成一次多选提问。
